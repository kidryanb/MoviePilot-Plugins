# kidryanb 的 MoviePilot V3 插件

在 MP 插件市场中添加本仓库地址 [kidryanb/MoviePilot-Plugins](https://github.com/kidryanb/MoviePilot-Plugins) 即可安装下面两个插件。两者可以装在同一个 MoviePilot 里，分工互不重叠。

| 插件 | 插件 ID | 版本 | 用途 |
| --- | --- | --- | --- |
| 网盘订阅助手（改版） | `CloudSubscribeFork` | `0.5.14` | 订阅搜网盘分享，同盘转存到 115 或夸克，可生成夸克 STRM |
| 下载完成自动上传 | `DownloadCloudUpload` | `0.4.0` | 下载器任务完成后按文件夹规则上传 115，保留本地文件 |

版本号以 [`package.v3.json`](package.v3.json) 为准，里面也有每个版本的更新说明。

另有两个配套工具，放在 [`tools/`](tools)：

| 工具 | 用途 |
| --- | --- |
| [quark-relay](tools/quark-relay/README.md) | 夸克 STRM 服务器中转：播放流量走服务器，不占 NAS 上行（插件 0.5.0 起支持） |
| [strm-relink](tools/strm-relink/README.md) | 修复 0.5.5 之前因 STRM 重写而断开的媒体库硬链接，一次性脚本 |

## 网盘订阅助手（改版）

版本：`0.5.14`。插件 ID `CloudSubscribeFork`，fork 自 [odomu/MoviePilot-Plugins](https://github.com/odomu/MoviePilot-Plugins) 的网盘订阅助手 v1.7.7，与原版 `CloudSubscribe` 可同时安装、互不覆盖。原版的使用说明见 [docs/cloudsubscribe.md](docs/cloudsubscribe.md)，改造计划见 [docs/cloudsubscribe-fork-plan.md](docs/cloudsubscribe-fork-plan.md)，源码说明见 [plugins.v3/cloudsubscribefork/README.md](plugins.v3/cloudsubscribefork/README.md)。

### 相对原版的主要改动

- **适配 MP V3**：入口与常用导入改为 `app.sdk`，依赖改用 `pyproject.toml`，附带构建好的配置页。
- **与「下载完成自动上传」共存**：PT 洗版上传固定关闭；新装默认只接管勾选的订阅、不拦截平台下载；115 Cookie 默认只读复用 P115StrmHelper；115 转存目录与上传目录重叠时停用 115。
- **同盘优先**：115 分享转存到 115，夸克分享转存到夸克，未登录的盘不会被写入。
- **夸克 STRM**：可生成夸克 STRM，支持经 [quark-relay](tools/quark-relay/README.md) 服务器中转播放。内容没变不重写，变了原地覆盖，硬链接到媒体库的那份同步更新（0.5.5）。
- **夸克改名与缓存（0.5.6）**：按 md5 或文件 ID 定位改名；目录、路径和分享缓存可在总览里统计和清理，覆盖所有已登录的网盘。
- **不再拿旧季或未播出的集占位（0.5.7）**：按 TMDB 播出日不搜、不转未播出的集（可设提前天数，可关闭）；季号识别支持第四季、S2、Season 2 和年份；文件名日期不属于本季或与播出日相差太多时拒绝；只有「第N期」没有上/下时不再猜集号；网盘和本地中转目录里已有的集不再重复搜索。
- **新入库 STRM 预读媒体信息（0.5.11，默认关）**：MP 把 STRM 整理进媒体库后，逐条让 Emby 提前分析媒体流，第一次播放不用现场分析；只处理单个条目、不刷新媒体库，限速并失败重试，可限定只处理某些来源目录。
- **quark-relay 1.1.0 内网取链和缓存（0.5.12）**：中转可另配 `MP_INTERNAL_URL` 走内网取直链（连不上自动退回 `MP_URL`），直链按过期时间缓存，夸克返回 403/410 时自动续签一次，播放途中过期也能续上；`LOG_LEVEL=DEBUG` 时逐请求记录取链、首包耗时和缓存命中（脱敏）。插件新增 `strm_relay_urls` / `strm_relay_choice` 为多地区中转预留，默认空，不影响旧配置。
- **离线任务修复（0.5.13）**：电视剧的磁力/ed2k 按排队时所在的网盘提交和监控（默认盘是夸克时交给 115）；115 离线任务按 info_hash 记录，下载失败立即识别并清理，不用等满超时；手动重试会清掉对应黑名单。
- **离线卡死与特别篇误绑（0.5.14）**：暂存目录有别的文件不再让磁力算作下载完成，卡在 0% 的任务到超时会删除；离线黑名单持久化（1 天）；115 已有同一 hash 未完成时不再重复提交；特别篇/SP/OVA 不再绑到普通季；能配上缺集的 115/夸克分享（含多季合集）先转存，磁力只做后手。
- **订阅缺集以 MP 为准**：按媒体服务器和订阅已下载记录计算，综艺「第N期上/下」按第 2N−1 / 2N 集识别。
- **搜索稳定性**：超时渠道立即让出并发名额；搜索代理可只给指定渠道使用，局域网地址直连；Cloudflare 质询判断更准，SeedHub 可用 FlareSolverr。

### AI 季集裁决（0.5.8 起）

MoviePilot 开启了 AI 智能体且 LLM 运行时就绪时，规则判不准的文件（没有本季季号或日期、靠「第N期上/下」换算、多季合集、加更花絮等）在转存前交给 AI 判断。AI 也没把握的进入待复核，不转存，并发送通知；在 MP 的 AI 助手里说「查看网盘订阅待复核」即可放行或拒绝。读取待复核列表不会写回数据。

MP 没开 AI 或运行时未就绪时，只走规则，行为与 0.5.7 相同。

自检接口 `GET /api/v1/plugin/CloudSubscribeFork/ai/selftest`（API Key 鉴权）在 MP 进程内跑一遍裁决，不转存。它用一个没有期号、日期和季号的样例文件名做注入测试，被放行即判失败，结果中返回 `passed` 和 `injection_blocked`。两次自检至少间隔 60 秒，并计入每日 AI 额度。

## 下载完成自动上传

版本：`0.4.0`，测试版。

监控 MoviePilot 中已经配置的 qBittorrent 和 Transmission。任务完成后，按用户设置的文件夹规则直接上传到 115，保留本地文件和做种任务。

### 当前状态

已实现双下载器监控、文件夹规则编辑、补传预览、持久队列、失败重试、上传进度、远端核对、STRM 目录接管、上传速度限制，以及任务页/仪表盘上传历史。仓库提供 `icons/cloud.png`，与 `plugin_icon` / `package.v3.json` 的 `cloud.png` 引用一致。

任务页区分本地校验进度、实际发送字节和115核对状态。秒传不经过字节传输回调，取得有效回执后显示100%。点击“刷新”更新当前插件弹窗；原生页面目前不自动轮询。重新上传需要在任务卡片中再次确认。

队列使用 SQLite WAL；页面通过限时只读快照读取状态。数据库暂时被锁时保留上次页面并显示提示，避免等待30秒后加载失败。成功、失败等终态会写入有上限的历史上传表，供任务页与仪表盘浏览。

请先用一个小视频联调，再启用日常任务。上传始终保留本地文件，没有自动覆盖或自动删除功能。

### 运行要求

- MoviePilot V3，提供 `app.sdk.services` 和一次性任务调度。
- 在 MP 中配置并启用 qBittorrent、Transmission 中需要监控的实例。
- MP 容器能够读取下载器保存的视频文件。
- 已安装 115 STRM 助手，并在其设置中保存有效 Cookie；使用该插件已经安装的 `p115client` 依赖。
- 网盘目标根文件夹已经存在。插件只按规则在其下创建需要的子文件夹。

本版本直接调用 115 客户端，不需要额外安装网盘储存插件。当前只支持 115。

### 安装

在 MP 插件市场中添加 [kidryanb/MoviePilot-Plugins](https://github.com/kidryanb/MoviePilot-Plugins)，然后安装“下载完成自动上传”。[v0.2.1 预发布包](https://github.com/kidryanb/MoviePilot-Plugins/releases/tag/v0.2.1)也可以用于本地仓库联调：

1. 解压源码，并将整个仓库映射进 MP 容器，例如 `/config/local-plugins/download-cloud-upload`。
2. 按 MP 的本地插件仓库配置，将该路径加入 `PLUGIN_LOCAL_REPO_PATHS`。
3. 重启或同步插件市场，确认能发现 `DownloadCloudUpload`。
4. 先配置下载器与文件夹规则，再开启插件。

本插件没有额外的 Python 依赖清单，使用 Python 标准库与 MP 已有依赖。不要在 Windows 上直接运行插件入口文件；它需要 MP 宿主。

### 复用 STRM 助手授权

在 115 STRM 助手中完成登录并保存设置，然后重新打开本插件设置。授权提示会显示是否读取到完整 Cookie；它只检查配置完整性，不代表网盘已验证登录成功。

读取字段为 `P115StrmHelper.cookies`，通过 MP 公开插件管理接口获取。上传操作会读取最新配置，不改写 STRM 助手设置，也不将 Cookie 复制到本插件配置、上传数据库或 GitHub。当前插件没有扫码、手动填写 Cookie 和储存选择入口。

DDSRem 插件仓库为 [DDSRem-Dev/MoviePilot-Plugins](https://github.com/DDSRem-Dev/MoviePilot-Plugins)。未找到 Cookie 时显示 `115_STRM_COOKIE_REQUIRED`；缺少其客户端依赖时显示 `115_STRM_CLIENT_REQUIRED`。

升级到 `0.2.0` 后关闭旧设置窗口再重新打开。原有 115 文件夹规则和上传队列保留；旧版本中配置的其他网盘任务会停止处理并显示 `ONLY_115_SUPPORTED`。旧储存后端生成的回执不能自动证明新版账号身份，同名文件无法确认时会报告冲突，不重新覆盖。

### 配置文件夹

在设置页填写规则，点击“加入或更新规则”，最后保存插件设置。可新增、选择、修改或删除多组规则。

点击“选择本地文件夹”或“选择网盘文件夹”，打开目录弹窗。点击文件夹可进入下一级，也可返回上级或回到根目录；点击“选择当前目录”后，路径自动填入对应字段。每页显示 20 个子文件夹，更多目录可翻页。目录读取失败时会显示提示，并禁止选择当前目录。

本地选择器浏览 MoviePilot 主机或容器中的目录，不是浏览器所在电脑的文件夹。下载器保存路径与 MP 挂载路径不同时，“下载器保存文件夹”仍需按下载器实际返回的路径填写。网盘选择器复用 STRM 助手的 Cookie，浏览目录不会创建文件夹或上传文件。弹窗状态和目录列表不会保存到插件配置。

目录选择使用 MP V3 提供的 `window.MoviePilotAPI` 请求客户端，沿用宿主登录状态。更新插件后，关闭旧设置窗口再重新打开。

| 设置项 | 示例 | 用途 |
| --- | --- | --- |
| 适用下载器 | 全部所选下载器 | 也可以仅用于某一个实例 |
| 下载器保存文件夹 | `/data/tv` | 下载器返回的路径前缀 |
| MP 可读取文件夹 | `/downloads/tv` | 同一批文件在 MP 容器中可见的位置 |
| 115 目标文件夹 | `/影视/电视剧` | 用户自行设置的上传位置 |
| 上传速度限制 | `1024`（KB/s） | `0` 或不填表示不限速；限制经 115 上传进度回调生效 |

下载器返回 `/data/tv/某剧/Season 01/第01集.mkv` 时，插件读取 `/downloads/tv/某剧/Season 01/第01集.mkv`，上传为 `/影视/电视剧/某剧/Season 01/第01集.mkv`。

两个本地路径相同时，填写相同路径即可。支持 Windows 下载器路径映射到 Linux MP 容器目录。规则按完整路径组件匹配，多条规则命中时使用来源文件夹最深的一条。同一来源存在冲突规则时不能启用。

### 首次启用和补传

首次成功读取每个下载器时，将已经完成的任务记为基线，不自动上传旧任务。首次读取时尚未完成的任务，之后完成会自动上传。停用后重新启用或普通重启不会重置基线。

补传步骤：

1. 在任务页点击“预览补传”，或勾选“保存后预览已有完成任务”。
2. 重新打开设置，在补传任务列表中选择需要上传的任务。
3. 勾选“保存后补传所选任务”并保存。

预览范围可选全部任务、最近 7 天或最近 30 天。完成时间未知的任务单独标明，仍需用户逐项选择。预览本身不上传，不修改完成基线。MP 的下载历史不用于判断任务是否完成。

### 日常上传

默认每 60 秒检查一次，文件稳定等待默认 10 秒。两个下载器分别查询，连接失败不会阻止另一个下载器工作。上传使用单工作线程串行执行，后端上传期间仍可继续检查下载器。

可在设置中填写「上传速度限制（KB/s）」；`0` 或不填为不限速。限速作用于 115 SDK 实际上传字节回调，不影响本地 SHA1 准备阶段；秒传不会产生字节传输，限速对其无意义。

QB 使用剩余字节、完成进度和原始任务状态判断。Transmission 使用所选文件剩余字节和任务状态判断。上传前再次核对所选文件已完成、路径未变化、文件大小符合清单。

默认处理视频文件，可选附带任务内的字幕及音轨。视频扩展名和排除路径关键词均可在设置页编辑；关键词不区分大小写，按任务内文件相对路径匹配。

上传记录保存于插件数据目录的 `queue.sqlite`，不写入 MP 的业务数据表。成功记录长期保留用于去重，不要随意删除数据库。历史上传表单独保留最近约 200 条终态结果（成功/已存在/失败/冲突/忽略），供页面浏览，并会裁剪过旧的事件日志。

### 上传历史

任务页底部显示「近期上传记录」，仪表盘可添加「上传历史」组件。每条记录包含时间、标题、源文件名、115 目标路径、状态、大小和错误摘要。历史接口 `/history` 支持分页；展示内容已脱敏，不包含 Cookie、本机绝对路径或凭据。

### 核对与冲突

插件保存本地 SHA-256 和上传回执。网盘有同名文件时，不能仅凭同名或同大小认为内容一致。当前去重只使用本地内容哈希与本插件可信回执，因此原本就在网盘中、又没有本插件可信回执的同名文件会显示冲突。

两个下载器的文件上传到同一位置时，只有本地内容哈希一致、已有成功回执且远端文件标识一致才跳过第二次上传。

上传接口返回后仍会查询远端，核对文件标识和大小。该核对证明本插件上传回执对应的文件存在，不等于逐字节重新下载验证。115 回执包含账号身份，避免不同账号的文件标识碰巧相同而误判。重复同名目录或文件会阻止继续操作。

### 失败处理

上传前发生查询或目录创建错误时，默认最多自动重试 5 次，间隔为 1、5、15、30、60 分钟。原始服务异常统一转换为固定错误码，不将凭据写入本插件任务记录或日志。

上传调用超时或没有明确回执时，先进入“待核对”，不盲目重复上传。如果无法确认原上传结果，需要用户处理：

- “重试或重新核对”：对已尝试上传的文件重新查询网盘，不重新写入。
- “确认后端已停止且远端不存在，重新上传”：先由用户确认旧上传已结束，再选择此操作。插件仍会严格查询目标；远端已存在时拒绝重新上传。
- “重新匹配目标”：仅用于尚未尝试上传的文件，成功文件不会搬移。
- “忽略”：停止自动处理所选文件，保留文件和记录。

长时间没有结果的上传需要实机判断。当前版本没有后端专用账号熔断、限流识别或独立上传取消功能；这些错误按通用服务错误处理，源文件不会删除。

离线测试仅需要 Python 和 Pydantic，使用标准库 `unittest`。从仓库根目录运行：

覆盖双下载器完成与暂停状态、首次基线、旧任务补传、目录映射、Windows 路径、未完成文件、重复扫描、跨下载器去重、同名冲突、失败重试、回执恢复、上传锁、源文件保留、速度限制与上传历史。

API 使用 MP 的 Bearer 认证，并要求超级管理员。接口位于 `/api/v1/plugin/DownloadCloudUpload/`：

| 路径 | 方法 | 用途 |
| --- | --- | --- |
| `/check` | POST | 提交立即检查 |
| `/preview` | POST | 生成只读补传列表 |
| `/folders` | POST | 只读浏览 MP 本地或 115 网盘目录 |
| `/backfill` | POST | 提交预览中选择的任务 |
| `/action` | POST | 处理所选文件记录 |
| `/mapping` | POST | 只读测试路径映射 |
| `/history` | POST | 分页查看上传历史 |
| `/status` | GET | 刷新任务页状态 |
